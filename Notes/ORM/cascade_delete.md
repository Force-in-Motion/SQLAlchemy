# Как правильно делать каскадное удаление

Каскадное удаление — это механизм, при котором удаление записи в родительской таблице (например, `User`) автоматически удаляет связанные записи в дочерней таблице (например, `Post` или `Profile`). В SQLAlchemy это настраивается на двух уровнях: уровне базы данных (DB-level) и уровне ORM (ORM-level). Вот как это работает:

## Уровень базы данных (DB-level)

Это настройка внешнего ключа в PostgreSQL, которая работает независимо от Python-кода. При удалении записи из `User` БД автоматически удаляет связанные записи в `Post` и `Profile`. Это обеспечивает целостность данных на уровне БД и работает даже при прямом SQL-запросе (например, `DELETE FROM "User" WHERE id = 1`).

* **Как настроить**:
  В дочерней таблице (`Post` или `Profile`) в `ForeignKey` укажи `ondelete="CASCADE"`:
  ```python
  user_id: Mapped[int] = mapped_column(ForeignKey("User.id", ondelete="CASCADE"))
  ```
* **Плюсы**:
  * Работает всегда, даже вне SQLAlchemy (например, в pgAdmin или скриптах).
* **Минусы**:
  * Не управляет объектами в памяти Python (ORM).

## Уровень ORM (ORM-level)

Это настройка в `relationship` на стороне родительской таблицы (`User`), которая управляет каскадом при операциях с объектами в сессии (например, `session.delete(user)`). Она определяет, что делать с связанными объектами в памяти.

* **Как настроить**:
  В `relationship` у родителя укажи `cascade="all, delete-orphan"`:

  ```python
  posts: Mapped[list["Post"]] = relationship(
      back_populates="user", lazy="select", cascade="all, delete-orphan"
  )
  ```

  * `all`: Каскадирует все операции (`save-update`, `merge`, `refresh-expire`, `expunge`, `delete`).
  * `delete-orphan`: Удаляет "осиротевшие" записи (например, посты, у которых удалён пользователь).
* **Плюсы**:

  * Работает на уровне объектов Python, автоматически удаляет связанные объекты при `session.delete(user)`.
* **Минусы**:

  * Не работает при прямом SQL-запросе, только через ORM.

## Нужно ли `cascade="all, delete-orphan"` в `User` или достаточно `ondelete="CASCADE"` в `Post` и `Profile`?

### Достаточно ли `ondelete="CASCADE"`?

* **Да**, если ты удаляешь записи напрямую через SQL-запросы (например, `DELETE FROM "User" WHERE id = 1;`). БД сама удалит связанные посты и профили.
* Это минимальный и надёжный способ для целостности БД, работает даже без SQLAlchemy.

### Нужно ли добавлять `cascade="all, delete-orphan"`?

* **Да**, если ты используешь ORM для удаления объектов (например, `session.delete(user); session.commit()`). Это обеспечивает, что связанные объекты (`posts`, `profile`) удаляются в памяти Python и синхронизируются с БД.
* В твоём коде это полезно для метода `del_user`, где ты удаляешь пользователя через ORM:
  ```python
  await session.delete(user_model)
  await session.commit()
  ```
* Без `cascade="all, delete-orphan"` связанные посты и профиль останутся в БД (если нет `ondelete="CASCADE"`), но с `ondelete="CASCADE"` они удалятся в БД, а `cascade` обеспечит правильную обработку в ORM (например, удаление orphans — постов, у которых нет пользователя).
